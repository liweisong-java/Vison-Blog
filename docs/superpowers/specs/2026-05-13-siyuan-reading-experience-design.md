# 思源式阅读体验改造设计

## 背景

当前博客已经完成了轻量化重构，具备以下基础能力：

- 思源驱动的内容同步与导出流程
- Astro 静态博客前台
- 中文优先的博客信息架构
- 服务器主导的自动同步、构建与部署链路

现阶段的主要问题已经不再是“能不能发出来”，而是“发出来之后读起来像不像在思源里整理完成的一篇笔记”。

用户这次的明确目标不是重写发布系统，也不是追求思源块结构的原样复刻，而是：

`保留博客站点感，但让文章正文页的阅读体验强烈贴近思源默认深色主题，同时把首页、技术、生活、归档这些列表页收敛到更适合中文内容的形态。`

## 目标

本次改造需要同时满足以下目标：

- 文章正文页明显贴近思源默认深色阅读体验
- 首页、技术、生活、归档四类列表页保留博客站点感，但弱化装饰感和说明性文案
- 中文长文的段落、标题、列表、引用、代码块、表格、图片阅读更自然
- 桌面端与移动端都保持稳定、克制、可持续扩展的样式体系
- 不改动现有思源同步、内容导出、自动发布主链路

## 非目标

本次明确不做以下事项：

- 不把整站改造成思源编辑器式界面
- 不把文章渲染链路升级为思源原生块结构渲染
- 不重写发布器导出逻辑
- 不为每种文章类型建立完全独立的页面模板
- 不重新设计关于我页和私有统计页
- 不引入新的前端框架或重型运行时交互

## 用户已确认的范围

用户已经确认的选择如下：

- 一致性目标：`A. 阅读样式像`
- 页面范围：`B. 文章正文页 + 列表页（首页 / 技术 / 生活 / 归档）`
- 参考主题：`B. 思源默认深色主题`
- 整体取舍：`B. 保留博客站点感，但正文区强烈贴近思源`
- 推荐路线：`B. 样式 + 阅读壳升级`

因此本次设计的核心不是“像素级复刻思源”，而是围绕阅读体验做一次展示层重构。

## 现状问题

### 1. 正文页仍然偏博客模板，不像笔记阅读页

当前文章页已经具备标题、摘要、封面、正文、目录、相关文章、评论等功能，但整体验证下来仍然更像“统一内容模板”，而不是“在思源里阅读一篇已经整理好的中文笔记”。

主要问题包括：

- 页头信息层级还不够像文档页
- 正文宽度、节奏、留白对中文长文不够友好
- 目录区的视觉存在感偏强
- 正文块之间的层级感还不够稳定

### 2. 列表页说明感偏强，索引感不够

首页、技术、生活、归档等页面虽然已经完成中文化，但部分区域仍保留了较强的说明性语言和展示型结构。

对个人博客而言，这会带来两个问题：

- 页面不像在“翻自己的内容”
- 信息密度和阅读入口不够直接

### 3. 中文阅读细节还没有真正按思源习惯校准

当前样式虽然已经比早期版本更克制，但对于中文博客最敏感的细节还不够稳：

- 标题和正文之间的呼吸感
- 中文段落自然换行的节奏
- 多级列表的缩进和扫描效率
- 引用、代码块、表格的低干扰阅读状态
- 移动端下的连续阅读体验

## 设计原则

### 1. 博客仍然是博客

首页、分类页、归档页仍然保留博客站点的公共骨架与导航关系，不会把整站做成“在线文档后台”。

### 2. 点进文章后，阅读体验明显切换

用户进入文章页后，应当明显感觉到页面从“站点入口”切换到了“沉浸阅读页”。这种切换主要通过版心、色板、正文层级、目录权重和留白节奏实现。

### 3. 中文阅读优先于装饰表达

所有视觉决策优先满足中文长文阅读，而不是追求更强的展示效果。能减掉的装饰尽量减掉，能用层级解决的问题不靠花哨样式解决。

### 4. 统一公共样式，不为单篇文章硬编码

这次改造要服务未来持续发布的文章，而不是只为某一篇文章调样式。所有规则都必须能稳定覆盖：

- 中文技术长文
- AI 使用心得
- 生活随笔
- 含代码、表格、图片、引用、列表的复合内容

## 方案对比

### 方案 A：纯样式贴近

只修改现有 CSS，不调整页面骨架。

优点：

- 实现快
- 风险小
- 不影响现有模板结构

缺点：

- 只能局部变像
- 文章页整体阅读姿态变化有限
- 列表页很难真正收敛成“个人内容索引”

### 方案 B：样式 + 阅读壳升级

在保留现有内容链路的前提下，同时升级文章页骨架、目录区、列表页版式和内容排版系统。

优点：

- 最符合用户的目标取舍
- 能明显提升正文页的思源感
- 也能把首页 / 分类 / 归档统一收拢成更成熟的中文博客站点

缺点：

- 改动范围比纯样式更大
- 需要同时处理桌面端和移动端细节

### 方案 C：双模式并存

保留当前博客模式，再新增一个“思源阅读模式”。

优点：

- 灵活
- 可以并行比较两套体验

缺点：

- 维护成本高
- 当前阶段收益不如复杂度大

## 选定方案

采用 `方案 B：样式 + 阅读壳升级`。

原因：

- 用户明确希望“站点感保留，但正文区强烈贴近思源”
- 只改 CSS 不足以完成这种切换感
- 双模式对当前项目体量来说过重
- 现有同步与发布链路已经稳定，最合理的改动面就是展示层

## 页面级设计

## 1. 文章正文页

### 1.1 页面定位

文章页需要从“通用内容页”升级为“中文笔记阅读页”。

目标感受是：

- 进入页面时仍知道自己在博客里
- 开始阅读后，注意力快速集中到正文
- 长时间滚动时不累、不散、不跳

### 1.2 页头结构

页头保留必要元信息，但不再堆放无关说明。

保留：

- 分类
- 发布日期
- 标题
- 导语 / 摘要

弱化或移除：

- 不必要的说明性标签
- 抢视觉的项目介绍文字
- 会打断阅读起始的辅助信息

如果文章存在 `canonicalUrl`，应降级为正文末尾的次要来源信息，而不是首屏重点内容。

### 1.3 正文阅读区

正文是本次改造的核心。

需要重点收敛以下维度：

- 版心宽度
- 正文字号
- 行高
- 段间距
- 标题层级间距
- 中文断行与词句扫描体验

目标不是把正文做得“宽松空洞”，而是做得“稳定、顺着往下读”。

### 1.4 标题系统

标题要更像文档层级，而不是营销卡片标题。

规则：

- `h1` 只承担文章页主标题
- `h2` 是主要章节锚点，要有明显但克制的分隔感
- `h3` 作为次级结构，需要足够清楚，但不抢 `h2`
- `h4` 继续弱化，避免层级堆叠过重

不采用大块背景标题、过厚描边、过强装饰符号。

### 1.5 常见内容块

正文样式需要重点统一以下块：

- 段落
- 有序 / 无序列表
- 引用
- 行内代码
- 代码块
- 表格
- 图片与图注
- 分割线

视觉方向：

- 引用更低对比、更安静
- 代码块更像阅读中的编辑器面板
- 表格更像笔记里的信息表
- 图片边距与说明更统一
- 分割线更轻，不打断节奏

### 1.6 目录系统

桌面端保留目录，但定位为轻量导航辅助。

要求：

- 视觉权重低于正文
- `sticky` 保留
- 长目录允许内部滚动
- `H2` 为主，`H3` 为辅
- 超长中文标题允许自然换行

移动端不再让目录在正文前占用过多空间，应收为轻量可展开区。

### 1.7 文章附加模块

相关文章和评论区继续保留，但要遵守一个原则：

`只有在模块已经构成“完成态”时才显示。`

因此：

- 相关文章只在有真实相关推荐时展示
- 评论区只在配置完整、体验完整时展示
- 附加模块的视觉层级低于正文完成态

## 2. 首页

首页定位调整为“最近在写什么”，而不是“项目说明页”。

改造方向：

- 首屏减少说明性文字
- 保留站点名与必要导航
- 直接把最近更新内容作为核心入口
- 分类筛选继续保留，但收敛视觉装饰

首页最重要的是让人快速看到：

- 最近写了什么
- 哪些内容属于技术 / 生活
- 从哪里继续往下读

## 3. 技术 / 生活列表页

这两个页面统一成同一套“文集索引页”模板。

规则：

- 顶部只保留页名和必要导航关系
- 移除解释型文案
- 文章列表直接成为页面主体
- 列表卡片更像笔记条目，而不是展示海报

每张卡片优先展示：

- 标题
- 日期
- 分类
- 阅读时长
- 2 到 3 行摘要

### 4. 归档页

归档页定位为“时间索引”，不是装饰型专题页。

结构方向：

- 按年 / 月组织
- 每篇文章以轻量条目或极简卡片呈现
- 标题与日期优先
- 尽量减少多余描述

目标是让用户像在翻自己的时间线，而不是在看一个被包装过的展示页面。

## 视觉系统方向

### 色板

以思源默认深色阅读体验为参考，但不直接复制编辑器界面。

重点统一以下颜色角色：

- 页面背景
- 面板背景
- 正文字色
- 次级文字
- 分隔边框
- 引用块底色
- 代码块底色
- 交互悬停与激活态

### 组件气质

整体气质关键词：

- 克制
- 稳定
- 低干扰
- 信息密度适中
- 中文长读友好

避免：

- 过强的渐变展示感
- 过多说明性副标题
- 过重卡片边框和投影
- 视觉中心四处分散

## 响应式策略

本次改造必须把移动端视为正式场景，而不是桌面端缩放结果。

重点要求：

- 文章正文在手机端依旧保持舒适宽度和合理字级
- 代码块、表格、图片允许横向滚动或收敛处理，但不能破版
- 移动端目录必须明显弱化
- 首页和分类页在手机端保持清爽，避免首屏信息拥堵
- 归档页的时间索引在小屏下仍然易扫读

## 技术实现边界

本次主要改动以下区域：

- `apps/blog/src/pages/posts/[slug].astro`
- `apps/blog/src/pages/index.astro`
- `apps/blog/src/pages/category/[category].astro`
- `apps/blog/src/pages/archive.astro`
- `apps/blog/src/components/PostCard.astro`
- `apps/blog/src/components/ArticleToc.astro`
- `apps/blog/src/styles/global.css`

必要时可以补充少量展示层辅助函数，但不改动以下核心机制：

- 思源 API 调用逻辑
- Markdown / MDX 导出与写入流程
- 自动同步发布脚本
- 服务器部署流程

## 风险与控制

### 风险 1：中文换行与段落节奏失衡

控制方式：

- 以真实中文文章回归，不只看空白模板
- 同时回归长段落、短段落、列表段落

### 风险 2：代码块、表格在移动端溢出

控制方式：

- 明确给出小屏滚动策略
- 在桌面端和移动端分别检查典型技术文章

### 风险 3：列表页收得太狠后显得无层次

控制方式：

- 用信息层级而不是装饰层级建立区分
- 保留必要的卡片边界、悬停反馈和摘要节奏

### 风险 4：只适配少量样例文章

控制方式：

- 至少用多篇不同结构的文章做回归
- 不为单篇内容写特例样式

## 验收标准

完成后需要满足以下结果：

- 正文页明显更接近思源默认深色阅读感
- 中文段落、标题、列表、引用、代码块、表格比当前版本更顺眼
- 首页与分类页更克制，减少说明文字，但仍保留博客站点感
- 归档页更像时间索引，浏览效率更高
- 桌面端和移动端都能稳定阅读
- 不影响现有思源同步和自动发布流程

## 验证计划

实现完成后至少执行以下验证：

- `pnpm --filter blog test`
- `pnpm --filter blog e2e`
- `pnpm check`

同时进行人工回归：

- 纯中文长文
- 含多级标题的技术文
- 含代码块 / 列表 / 引用 / 表格的文章
- 首页
- 技术页
- 生活页
- 归档页
- 移动端文章页与列表页

## 实施结论

这次改造应被视为：

`在不动内容主链路的前提下，对博客展示层进行一次面向中文阅读体验的系统升级。`

最终目标不是把博客变成思源本体，而是让它在公开发表场景下，尽量保留思源里那种稳定、克制、适合长文阅读的感觉。
