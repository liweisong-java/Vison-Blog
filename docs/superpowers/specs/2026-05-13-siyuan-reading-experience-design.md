# 思源友好型博客发布与阅读体验改造设计

## 背景

当前博客已经完成从旧项目壳子到轻量化 Astro 博客的重构，并具备以下基础能力：

- 思源驱动的内容同步与导出流程
- Astro 静态博客前台
- 中文优先的博客信息架构
- 服务器主导的自动同步、构建与部署链路

这意味着项目已经跨过了“能不能发出来”的阶段，进入“发出来之后稳不稳、像不像自己在思源里整理好的内容”的阶段。

用户这次新增的核心要求不是单纯把页面改得更像思源，而是：

`以后在思源里正常写内容，尤其是带思源特色结构的内容，也能足够健壮地同步到博客，并在博客里稳定、可读、长期可维护。`

因此，这次改造不能只做展示层美化，而要同时完成两条主线：

- 发布器的思源语义兼容层
- 博客前端的中文阅读体验升级

## 目标

本次改造需要同时满足以下目标：

- 让思源中的常见写法和第一批重点特色结构能稳定发布到博客
- 让博客正文页明显贴近思源默认深色主题的阅读感
- 让首页、技术、生活、归档这些列表页更像中文个人博客的内容索引
- 对复杂思源结构提供“语义优先”的稳定降级，而不是结构错乱
- 保持桌面端与移动端都可读、可维护、可持续扩展
- 不推翻当前已经跑通的服务器主导同步、构建与部署主链路

## 非目标

本次明确不做以下事项：

- 不追求思源块结构的像素级原样复刻
- 不把整站改造成思源编辑器式后台
- 不重写整个发布系统或替换思源 API 调用方式
- 不为每一种思源私有高级块玩法都承诺第一阶段全自动支持
- 不新增重型前端框架或复杂运行时交互
- 不重新设计关于我页和私有统计页

## 用户已确认的范围

用户已经确认的关键选择如下：

- 一致性目标：`A. 阅读样式像`
- 页面范围：`B. 文章正文页 + 列表页（首页 / 技术 / 生活 / 归档）`
- 参考主题：`B. 思源默认深色主题`
- 整体取舍：`B. 保留博客站点感，但正文区强烈贴近思源`
- 兼容重点：`B. 支持思源特色结构`
- 兼容取舍：`A. 语义优先`
- 推荐路线：`发布器语义转换 + 阅读壳升级`

因此这次设计的核心不再是“前端改得更像思源”，而是：

`让博客成为一个对思源写作方式足够友好的稳定发布目标。`

## 现状问题

### 1. 当前发布器主要是“清洗 Markdown”，不是“理解思源结构”

目前 `tools/publisher/src/markdown.ts` 的主要职责是：

- 去除原始 frontmatter
- 去除重复标题
- 清理不可见字符
- 重写资源路径
- 生成 MDX

这条链路对普通 Markdown 已经足够稳定，但对以下内容缺少专门兼容层：

- 折叠块
- 提示块 / 说明块
- 块引用
- 嵌入块
- 分栏
- 复杂嵌套结构

因此，一旦用户在思源中开始更自然地使用特色块，博客端就容易出现：

- 结构保不住
- 表现不统一
- 移动端容易乱
- 新文章写法一变就需要重新补样式

### 2. 正文页仍然偏博客模板，不像笔记阅读页

当前文章页已经具备标题、摘要、封面、正文、目录、相关文章、评论等功能，但整体仍更像通用博客模板，而不是“在思源里阅读一篇整理好的中文笔记”。

主要问题包括：

- 页头信息层级还不够像文档页
- 正文宽度、节奏、留白对中文长文不够友好
- 目录区的视觉存在感偏强
- 正文块之间的层级感还不够稳定

### 3. 列表页说明感偏强，索引感不够

首页、技术、生活、归档等页面虽然已经中文化，但部分区域仍保留了较强的说明性语言和展示型结构。

对个人博客而言，这会带来两个问题：

- 页面不像在“翻自己的内容”
- 阅读入口和浏览效率还不够直接

### 4. 中文阅读细节还没有真正按思源习惯校准

当前样式虽然已经比早期版本更克制，但对于中文博客最敏感的细节还不够稳：

- 标题和正文之间的呼吸感
- 中文段落自然换行的节奏
- 多级列表的缩进和扫描效率
- 引用、代码块、表格的低干扰阅读状态
- 移动端下的连续阅读体验

## 设计原则

### 1. 语义优先于外观复刻

对思源特色块，优先保证含义不丢、结构不乱、顺序不坏；外观接近属于第二层目标。

### 2. 博客仍然是博客

首页、分类页、归档页仍然保留博客站点的公共骨架与导航关系，不会把整站做成“在线文档后台”。

### 3. 进入文章后，阅读体验明显切换

用户进入文章页后，应当明显感觉到页面从“站点入口”切换到了“沉浸阅读页”。这种切换主要通过版心、色板、正文层级、目录权重和留白节奏实现。

### 4. 中文阅读优先于装饰表达

所有视觉决策优先满足中文长文阅读，而不是追求更强的展示效果。能减掉的装饰尽量减掉，能用层级解决的问题不靠花哨样式解决。

### 5. 稳定支持优先于一次性支持一切

第一阶段聚焦最常见、最有价值的思源结构，把支持做稳；对于极少数高度私有化玩法，先保证可读降级，而不是承诺完全自动化。

## 方案对比

### 方案 A：只改前端样式

继续沿用当前 Markdown / MDX 直出链路，只重做文章页和列表页样式。

优点：

- 快
- 风险低
- 不影响当前内容链路

缺点：

- 无法满足“以后在思源里复杂写也要稳”的核心要求
- 思源特色块仍然缺乏稳定语义映射
- 后续每出现一种新写法都容易补洞

### 方案 B：发布器做语义转换 + 前端阅读壳升级

在思源导出 Markdown 之后，发布器先识别并转换思源特色结构，统一生成博客内部语义块；前端再围绕这些统一语义做阅读体验升级。

优点：

- 最符合用户真实需求
- 长期最稳
- 前后端职责清晰
- 后续新增支持范围时可持续扩展

缺点：

- 改动面比纯样式大
- 需要同时补充发布器测试和前端测试

### 方案 C：双通道兼容

普通内容继续走现有发布链路，检测到特色结构时单独走一套兼容流程。

优点：

- 看起来风险可控

缺点：

- 内部流程会变复杂
- 规则容易分散
- 后续维护成本更高

## 选定方案

采用 `方案 B：发布器语义转换 + 前端阅读壳升级`。

原因：

- 用户明确要求后续思源写作方式要能稳
- 单纯改前端不解决根因
- 当前同步、构建、部署链路已经稳定，最合理的扩展点就是在发布器里增加语义兼容层
- 前端只有消费统一语义层，阅读体验升级才不会变成长期补洞

## 支持范围设计

### 一级支持：必须稳定还原语义

以下内容作为第一阶段正式能力，目标是“正常写，稳定发”：

- 标题层级
- 普通段落
- 粗体、斜体、删除线、行内代码
- 有序 / 无序 / 多级列表
- 引用块
- 代码块
- 表格
- 图片、图片说明
- 分割线
- 链接
- 折叠块
- 提示块 / 说明块
- 块引用
- 嵌入块
- 分栏

### 二级支持：允许降级，但不能乱

以下内容允许降级表达，但语义和阅读顺序不能坏：

- 复杂嵌套列表
- 多层折叠套折叠
- 引用里再嵌引用
- 分栏里混复杂块
- 特殊对齐或局部排版

原则是：

- 优先保语义
- 其次保顺序
- 最后才保外观

### 三级支持：暂不承诺完全自动化

以下内容第一阶段不承诺无脑稳定，但至少要做到“不炸页面、可读降级”：

- 思源高度私有化的高级块玩法
- 强依赖编辑器交互的块
- 很重的布局型组合块

## 发布器语义兼容层

### 总体思路

发布链路升级为：

`思源导出 Markdown -> 基础清洗 -> 思源结构识别 -> 语义块转换 -> 资源路径重写 -> 生成 MDX`

核心变化是：

- 发布器不再只是清洗 Markdown
- 发布器开始负责“把思源内容翻译成博客认识的内部语义”

### 识别策略

第一阶段不引入过重的内容工程，而采用“规则识别 + 保守降级”的稳妥路线：

- 先基于思源导出的 Markdown 特征做规则识别
- 对明确可识别的结构做稳定转换
- 对难以完全确认的结构做保守降级

第一批重点识别：

- 折叠块
- 提示块
- 引用 / 块引用
- 嵌入块
- 分栏标记
- 图片说明与图文组合
- 特殊分隔结构

### 统一语义输出

发布器输出的不是散乱 HTML，而是博客内部统一的语义标记。

可采用的输出形态包括：

- `:::callout type="note"` ... `:::`
- `:::quote-block` ... `:::`
- `:::embed-card kind="block-ref"` ... `:::`
- `:::columns` ... `:::`
- `details / summary`
- 极少量受控 HTML 容器

原则：

- 前端只需要认识这一套统一语义
- 不直接把思源私有结构泄漏到前端
- 以后新增能力时扩展这套语义层即可

### 思源结构到博客语义的映射

第一阶段建议采用以下映射策略：

- 折叠块 -> `details / summary` 语义折叠区
- 提示块 / 说明块 -> 统一 `callout` 语义块
- 块引用 -> 统一“引用内容块”，保留来源感
- 嵌入块 -> 统一“嵌入内容卡”或“引用片段块”
- 分栏 -> 桌面端允许并排，移动端自动降级为上下堆叠

### 降级策略

对无法 100% 稳定识别或过于复杂的结构，执行统一降级规则：

- 能保语义，就转成对应语义块
- 不能稳保语义，就降级成普通区块 + 清晰层次
- 再不行，也必须保证整篇文章可读，不出现结构断裂或页面炸掉

示例：

- 分栏识别不稳 -> 自动降级为上下段落块
- 复杂嵌入 -> 降级为“引用片段卡”
- 多重折叠 -> 保留外层折叠，内层降级为普通块

## 博客前端阅读体验升级

## 1. 文章正文页

### 1.1 页面定位

文章页需要从“通用内容页”升级为“中文笔记阅读页”。

目标感受是：

- 进入页面时仍知道自己在博客里
- 开始阅读后，注意力快速集中到正文
- 长时间滚动时不累、不散、不跳

### 1.2 页头结构

页头保留必要元信息，但不再堆放无关说明。

保留：

- 分类
- 发布日期
- 标题
- 导语 / 摘要

弱化或移除：

- 不必要的说明性标签
- 抢视觉的项目介绍文字
- 会打断阅读起始的辅助信息

如果文章存在 `canonicalUrl`，应降级为正文末尾的次要来源信息，而不是首屏重点内容。

### 1.3 正文阅读区

正文是这次改造的前端核心。

需要重点收敛以下维度：

- 版心宽度
- 正文字号
- 行高
- 段间距
- 标题层级间距
- 中文断行与词句扫描体验

目标不是把正文做得“宽松空洞”，而是做得“稳定、顺着往下读”。

### 1.4 语义块展示

前端需要围绕发布器生成的内部语义块建立稳定样式：

- `callout`
- `quote-block`
- `embed-card`
- `columns`
- `details / summary`

这些样式的目标不是炫，而是安静、克制、层级清晰，并确保桌面端与移动端都可读。

### 1.5 目录系统

桌面端保留目录，但定位为轻量导航辅助。

要求：

- 视觉权重低于正文
- `sticky` 保留
- 长目录允许内部滚动
- `H2` 为主，`H3` 为辅
- 超长中文标题允许自然换行

移动端目录收为轻量可展开区，避免在正文前堆积过多结构。

## 2. 首页

首页定位调整为“最近在写什么”，而不是“项目说明页”。

改造方向：

- 首屏减少说明性文字
- 保留站点名与必要导航
- 直接把最近更新内容作为核心入口
- 分类筛选继续保留，但收敛视觉装饰

## 3. 技术 / 生活列表页

这两个页面统一成同一套“文集索引页”模板。

规则：

- 顶部只保留页名和必要导航关系
- 移除解释型文案
- 文章列表直接成为页面主体
- 列表卡片更像笔记条目，而不是展示海报

每张卡片优先展示：

- 标题
- 日期
- 分类
- 阅读时长
- 2 到 3 行摘要

## 4. 归档页

归档页定位为“时间索引”，不是装饰型专题页。

结构方向：

- 按年 / 月组织
- 每篇文章以轻量条目或极简卡片呈现
- 标题与日期优先
- 尽量减少多余描述

## 视觉系统方向

### 色板

以思源默认深色阅读体验为参考，但不直接复制编辑器界面。

重点统一以下颜色角色：

- 页面背景
- 面板背景
- 正文字色
- 次级文字
- 分隔边框
- 引用块底色
- 代码块底色
- 交互悬停与激活态

### 组件气质

整体气质关键词：

- 克制
- 稳定
- 低干扰
- 信息密度适中
- 中文长读友好

避免：

- 过强的渐变展示感
- 过多说明性副标题
- 过重卡片边框和投影
- 视觉中心四处分散

## 响应式策略

本次改造必须把移动端视为正式场景，而不是桌面端缩放结果。

重点要求：

- 文章正文在手机端依旧保持舒适宽度和合理字级
- 代码块、表格、图片允许横向滚动或收敛处理，但不能破版
- 移动端目录必须明显弱化
- 分栏在小屏下自动堆叠
- 嵌入块和引用块在小屏下仍然层级清晰
- 首页和分类页在手机端保持清爽，避免首屏信息拥堵
- 归档页的时间索引在小屏下仍然易扫读

## 技术实现边界

本次主要改动以下区域：

- `tools/publisher/src/markdown.ts`
- 必要时新增 `tools/publisher/src/` 下的内容规范化辅助模块
- `tools/publisher/tests/markdown.test.ts`
- 必要时补充 `tools/publisher/tests/sync.test.ts`
- `apps/blog/src/pages/posts/[slug].astro`
- `apps/blog/src/pages/index.astro`
- `apps/blog/src/pages/category/[category].astro`
- `apps/blog/src/pages/archive.astro`
- `apps/blog/src/components/PostCard.astro`
- `apps/blog/src/components/ArticleToc.astro`
- 必要时新增少量 MDX 语义块组件
- `apps/blog/src/styles/global.css`

本次不改动以下核心机制：

- 思源 API 调用逻辑本身
- 服务器主导同步 / 构建 / 部署主流程
- GitHub Actions 的总体发布模型

## 风险与控制

### 风险 1：思源特色结构识别误判

控制方式：

- 对每一种结构先写发布器测试
- 对不确定结构采用保守降级
- 不把“猜测性识别”直接强转为复杂语义

### 风险 2：普通 Markdown 内容被兼容层误伤

控制方式：

- 保留普通 Markdown 的回归测试
- 确保默认内容在未命中特色结构时仍走稳定路径

### 风险 3：前端新增语义块后样式过重或移动端炸裂

控制方式：

- 先建立低装饰、低耦合的统一语义块样式
- 专门回归移动端代码块、表格、分栏、嵌入块

### 风险 4：只对少量样例文章有效

控制方式：

- 用真实文章和专门样本同时回归
- 不为单篇内容写特例样式

## 验收标准

完成后需要满足以下结果：

- 思源中的普通内容和第一批特色结构能稳定同步到博客
- 折叠块、提示块、块引用、嵌入块、分栏具备统一且可维护的博客语义表达
- 无法稳定识别的复杂结构能可读降级，不炸页面
- 正文页明显更接近思源默认深色阅读感
- 首页、分类页、归档页更克制、更像内容索引
- 桌面端和移动端都能稳定阅读
- 不影响现有自动同步和自动部署主链路

## 验证计划

实现完成后至少执行以下验证：

- `pnpm --filter publisher test`
- `pnpm --filter blog test`
- `pnpm --filter blog e2e`
- `pnpm check`

同时进行人工回归：

- 一篇普通中文长文
- 一篇技术文，含代码块 / 列表 / 引用 / 表格
- 一篇包含折叠块、提示块、块引用、嵌入块、分栏的复杂笔记
- 首页
- 技术页
- 生活页
- 归档页
- 移动端文章页与列表页

## 实施结论

这次改造应被视为：

`在不推翻现有主链路的前提下，把博客升级为一个对思源写作方式更友好的稳定发布目标。`

最终目标不是把博客变成思源本体，而是让你以后在思源里正常写内容时，博客既能稳稳接住这些内容，又能用更成熟的中文博客方式把它们展示出来。
