# 个人中控台设计

## 目标

在当前博客项目中新增一个隐藏的“个人中控台”页面，用来承接你自己的日常操作，而不是面向访客的内容页。

这个页面的定位不是传统后台，也不是说明页，而是一个有产品感的私人工作台：

- 简单好记
- 移动端优先
- 第一屏就能完成最常用动作
- 同时保留后续扩展入口

## 页面定位

页面是：

- 私人使用
- 隐藏入口
- 操作优先
- 轻状态感

它不是：

- 公共导航页面
- 面向访客的介绍页
- 复杂后台管理系统
- 大量表格和数据堆砌页

## 路径与隐藏策略

路径固定为：

- `/desk/`

命名原因：

- 短
- 好记
- 有“个人工作台”的语义
- 比 `/go/` 更像产品，比 `/me/` 更像操作页

隐藏策略：

- 不进入主导航
- 不进入 sitemap
- 不进入 RSS
- 页面元信息使用 `noindex,nofollow,noarchive`

推荐继续保留现有私有页保护方式，例如：

- Nginx Basic Auth
- 只你自己知道路径

## 视觉方向

整体方向采用“产品化私人工作台”，而不是传统后台。

视觉关键词：

- 像一个独立 App 的首页
- 按钮更像入口卡片
- 信息克制
- 圆角更大
- 首屏更轻
- 移动端优先

不做的方向：

- 大面积后台表格感
- 一屏放太多统计
- 复杂侧边栏
- 冷冰冰的管理系统视觉

## 结构设计

页面分三层，但首屏只强调前两层。

### 1. 顶部欢迎卡

作用：

- 建立产品感
- 形成页面记忆点
- 给私人工作台一个明确的首页气质

内容：

- 小标题：`Vison Desk`
- 主标题：偏行动导向，例如“今天先处理什么？”
- 一句简短说明，不做长段落

要求：

- 视觉上像 App 首屏 hero
- 移动端第一眼就能识别

### 2. 快捷入口卡片区

这是首屏最重要的区域。

卡片形式：

- 两列网格
- 每个按钮像 App 图标卡片
- 包含简短标题与一句次级描述
- 点击区域足够大，适合手机操作

第一版固定入口：

- 博客
- 后台
- 关于我
- 更多

其中已确定的地址：

- 博客后台：`http://localhost:4321/secret-dashboard/index.html`

第一版“更多”先作为扩展占位，后续可以接：

- 思源
- 服务器面板
- GitHub 仓库
- 其他个人工具

### 3. 轻量状态提示

用户已经明确要求：

- 状态区不要太多

因此第一版状态区只保留一条很轻的摘要提示，不再放大面积状态面板。

示例形式：

- “发布正常，队列 2 条”
- “最近一次同步成功于 09:12”

要求：

- 放在首屏底部或操作卡之后
- 不抢主视觉
- 不替代现有完整私有统计页

## 与现有私有页的关系

当前已有：

- `/secret-dashboard/`

这个页面保留，继续作为详细统计页。

新增 `/desk/` 的定位是：

- 更像首页
- 更偏操作
- 更偏移动端使用

关系分工：

- `/desk/`：私人工作台首页
- `/secret-dashboard/`：详细统计与发布状态页

因此 `/desk/` 中只需要提供：

- 跳转到后台
- 一条轻状态摘要

而不是复制整个 dashboard。

## 移动端优先策略

这是本设计的最高优先级之一。

第一版默认按手机竖屏体验先设计，再向桌面端展开。

移动端要求：

- 单列信息流
- 两列入口卡片
- 大点击区
- 简短标题
- 输入区在一屏内尽量完整
- 状态提示只保留一条

桌面端展开策略：

- hero 更舒展
- 快捷入口和视频操作区可以拉成左右或上下更舒服的布局
- 但不改变移动端优先的信息顺序

## 第一版范围

第一版直接实现这些内容：

- 新增隐藏页面 `/desk/`
- 页面 `robots` 设为私有
- 不进入主导航
- App 感快捷入口卡片
- 博客入口
- 博客后台入口
- 一条轻状态摘要
- 移动端优先样式

## 第一版非目标

这一轮先不做：

- 完整的复杂后台交互
- 多区块统计堆叠
- 可视化图表
- 多标签页切换
- 登录体系
- 权限体系
- 真正复杂的任务历史中心

## 技术实现方向

建议基于现有 Astro 前台实现：

- 页面文件新增到 `apps/blog/src/pages/desk/index.astro`
- 尽量复用当前 `BaseLayout`
- 保持和现有私有页相同的 noindex 策略
- 新增局部样式到 `global.css`

## 文案与气质

文案风格要求：

- 中文
- 直接
- 少解释
- 更像你自己的工作台，而不是产品营销文案

避免：

- “欢迎来到……”
- “这里可以帮助你……”
- 过长说明文字

推荐：

- “今天先处理什么？”
- “一键整理视频”
- “进入博客”
- “发布正常，队列 2 条”

## 落地结论

第一版采用：

- 路径：`/desk/`
- 形态：产品化私人工作台
- 视觉：App 感入口卡片 + 轻量操作卡 + 极简状态提示
- 优先级：移动端第一、简单好记第一、产品感第一
