# 私有统计页面设计

## 背景

当前博客已经完成以下基础能力：

- 思源驱动的轻量内容发布链路
- Astro 静态博客前台
- GitHub Actions 自动构建与服务器静态部署
- 中文阅读优先的页面样式体系

博客本身面向公开访问，但用户还需要一个“只有自己知道”的页面，用来查看站点和发布链路的内部统计信息。

这个页面不是公开博客内容的一部分，而是面向站长本人使用的私有仪表盘。

## 目标

在不把整个博客改造成后台系统的前提下，为当前项目增加一个受保护的私有统计页。

这个页面需要同时承载三类统计：

- 内容统计
- 访问统计
- 发布链路统计

同时满足：

- 页面不在公开导航中出现
- 页面路径不进入 sitemap / RSS / 公开入口
- 访问前需要密码保护
- 不引入额外的鉴权服务
- 页面数据可以定时刷新，不要求近实时

## 非目标

本次明确不做：

- 自定义登录页 + 后端会话系统
- GitHub / OAuth 身份登录
- 实时流式仪表盘
- 复杂 BI 看板
- 多用户权限体系
- 单独新增第二套后台应用

## 已确认选择

用户已确认的约束如下：

- 私有页必须是真正私有，而不是仅靠隐藏 URL
- 访问统计需要新接轻量统计服务
- 访问统计不要求近实时，接受定时刷新
- 不接受为了自定义登录页再额外运行一个鉴权服务
- 最终采用服务器层密码保护
- 可接受在服务器上额外部署自托管 `Umami`

## 推荐方案

采用：

`受 Nginx Basic Auth 保护的私有静态仪表盘 + Umami 定时抓取 + 发布器状态文件`

这是当前项目约束下最稳妥、最轻量、也最容易维护的方案。

## 总体结构

系统分为四层：

1. 私有页面层
2. 数据生成层
3. 访问统计层
4. 服务器保护层

### 1. 私有页面层

博客中新增一个不公开入口的私有页面，例如：

`/secret-dashboard/`

该页面：

- 不出现在 Header 导航
- 不在首页展示任何入口
- 不进入 sitemap
- 不进入 RSS
- 不被普通文章或标签页引用

页面本身仍然是 Astro 页面，跟随现有博客一同构建部署。

### 2. 数据生成层

私有页不直接在浏览器里请求第三方统计 API，也不在页面运行时实时计算。

而是先由脚本定时生成结构化数据文件，再由页面读取这些文件。

生成结果建议统一落在私有页面目录下，例如：

```text
secret-dashboard/
  index.html
  data/
    dashboard.json
```

这样私有页面和私有数据可以一起被服务器保护。

### 3. 访问统计层

访问统计采用自托管 `Umami`。

博客公开页面埋入 Umami 统计脚本，私有仪表盘不直接依赖前端 SDK，而是通过定时任务从 Umami API 拉取摘要数据。

### 4. 服务器保护层

真正的访问保护由 `Nginx Basic Auth` 完成。

被保护的路径至少包括：

- `/secret-dashboard/`
- `/secret-dashboard/data/`

这样页面和数据文件都不会在未认证状态下暴露。

## 页面信息结构

私有页建议采用四段结构：

1. 顶部总览
2. 内容统计
3. 访问统计
4. 发布链路统计

### 顶部总览

这一层只展示 4 到 6 个最关键的数字卡片，例如：

- 总文章数
- 最近 30 天发文数
- 今日访问量
- 最近 30 天访问量
- 最近同步状态
- 最近成功发布时间

目标是让用户每次打开页面时，先快速扫一眼整体状态。

### 内容统计区

数据来源：`apps/blog/src/content/posts/**`

建议展示：

- 总文章数
- 技术 / 生活 分布
- 标签总数
- 最常用标签
- 最近 30 天发布量
- 发布时间趋势
- 总字数
- 平均每篇长度

这部分回答的问题是：

`这个博客现在写到了什么程度`

### 访问统计区

数据来源：`Umami`

建议展示：

- 今日 PV / UV
- 近 7 天 PV / UV
- 近 30 天 PV / UV
- 热门文章 Top N
- 来源 Top N
- 设备分布
- 访问趋势

这部分回答的问题是：

`最近哪些内容真的被看，访问表现如何变化`

### 发布链路统计区

数据来源：发布器状态文件

建议展示：

- 最近一次同步时间
- 最近一次成功发布时间
- 最近一次失败时间
- 最近一次失败原因
- 最近 7 天同步次数
- 当前待发布数量
- 发布器健康状态

这部分回答的问题是：

`思源 -> 博客 这条链路当前是否正常`

## 数据生成设计

### 统一生成目标

前端页面不分别读取多个零散统计文件，而是读取一份汇总后的：

`dashboard.json`

建议结构：

```json
{
  "generatedAt": "2026-05-12T12:00:00.000Z",
  "summary": {},
  "content": {},
  "traffic": {},
  "publisher": {}
}
```

这样页面层只负责展示，不负责再做拼装。

## 内容统计生成

内容统计由本仓库脚本直接读取内容集合生成。

输入来源：

- `apps/blog/src/content/posts/**`

输出内容：

- 文章数
- 分类分布
- 标签分布
- 发布时间分布
- 文章长度统计

这部分不依赖任何外部系统，稳定性最高。

## 访问统计生成

访问统计由定时任务从 Umami API 拉取后生成。

输入来源：

- Umami site / website 数据

建议只拉核心指标，不追求一次性覆盖所有字段。

推荐窗口：

- 今日
- 近 7 天
- 近 30 天

推荐生成频率：

- 每小时一次

这样既能保持新鲜度，又不会把系统复杂度拉高。

## 发布链路统计生成

发布统计不建议去解析 Git 历史作为主来源，而建议由发布器在同步流程里主动写出状态文件。

状态文件建议记录：

- 最后一次开始时间
- 最后一次完成时间
- 最后一次成功时间
- 最后一次失败时间
- 最后一次失败原因
- 最近 N 次同步摘要
- 当前待发布数量

这份状态文件可以由 `tools/publisher` 在每次发布后更新。

## 更新机制

建议拆成两条更新链路：

### 1. 内容统计 + 发布统计

在每次博客发布或同步流程结束时更新。

优点：

- 与内容变化同步
- 不需要独立轮询

### 2. 访问统计

由单独定时任务更新，例如：

- 每小时一次

优点：

- 数据足够新
- 不影响发布链路

## 安全边界

### 1. 页面入口不公开

私有页路径不进入：

- Header 导航
- 首页
- sitemap
- RSS
- 公开页面内部链接

### 2. Nginx 路径保护

服务器对私有页路径启用 Basic Auth。

示意范围：

- `/secret-dashboard/`
- `/secret-dashboard/data/`

### 3. 私有 JSON 同样受保护

不能出现“页面要密码，JSON 却公开可读”的情况。

因此私有数据文件必须与页面一起置于受保护路径下。

### 4. API Key 只保存在服务器或 Secret

以下内容不能进入前端或公开仓库：

- Umami API Key
- Umami 站点 ID 对应的私有操作凭据
- 统计抓取脚本用到的令牌

允许的存放位置：

- GitHub Secrets
- 服务器环境变量
- 服务器私有配置文件

## 部署设计

### 博客主站部署

继续沿用当前静态部署方式：

- GitHub Actions 构建
- 上传到 `/data/Vison-Blog/releases/<sha>`
- 切换 `current`

### 私有页部署

私有统计页作为博客静态产物的一部分一起部署。

它不是第二套服务，也不是第二个仓库。

这样：

- 部署方式统一
- 回滚一致
- 维护成本最低

### Umami 部署

Umami 作为单独统计服务部署在同一台服务器上。

它不承担博客鉴权，只承担访问统计采集与 API 数据源角色。

## Nginx 设计要点

建议：

- 公开博客根路径照常提供静态访问
- 对 `/secret-dashboard/` 开启 `auth_basic`
- 对 `/secret-dashboard/data/` 同样开启 `auth_basic`

这样只增加一小段服务器配置，不会改变公开博客的工作方式。

## 用户体验设计

用户访问流程：

1. 输入私有页 URL
2. 浏览器弹出密码框
3. 输入用户名密码
4. 进入统计仪表盘

虽然不是自定义登录页，但这是当前“不加额外鉴权服务”前提下唯一真正安全的轻量实现。

## 兼容性与扩展性

后续可扩展方向：

- 增加更多内容趋势图
- 增加系列文章进度
- 增加发布失败明细页
- 增加流量来源细分
- 将 Basic Auth 升级为更完整的登录方式

本次设计要求不阻断这些未来升级。

## 实现边界建议

建议新增这些能力：

- 私有仪表盘 Astro 页面
- 私有统计数据 schema
- 内容统计生成脚本
- Umami 拉数脚本
- 发布器状态输出文件
- 仪表盘定时更新任务说明
- 服务器 Nginx 配置说明

## 验收标准

完成后应满足：

1. 公开博客中没有任何私有页入口
2. 私有页路径需要密码才能访问
3. 私有 JSON 数据也受同样保护
4. 私有页能展示内容统计、访问统计、发布统计三大区块
5. 内容统计能正确反映当前博客内容状态
6. 访问统计能从 Umami 定时同步并展示
7. 发布统计能显示最近同步和失败状态
8. 页面仍然保持博客现有的中文风格和轻量阅读感

## 结论

本次私有统计页不应被实现成“隐藏链接的普通页面”，也不应被实现成“额外的重后台系统”。

最佳落点是：

`受 Nginx Basic Auth 保护的私有静态仪表盘 + Umami 定时抓取 + 发布器状态文件`

这最符合当前博客项目的轻量架构和长期维护目标。
